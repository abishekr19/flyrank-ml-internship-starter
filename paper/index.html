Refresh / Content Opportunity Scoring

A machine-learning approach for prioritizing search discoverability and content improvement opportunities

FlyRank ML Internship Capstone

Abstract

This research asks whether historical search-performance signals can help prioritize webpages that may require content investigation or improvement. A classification-based machine-learning approach was developed using page-level search-performance features from February 2026 and a March 2026 outcome window. The model was compared with a transparent Week 4 baseline rule using the same held-out test split. The ML model achieved a ROC-AUC of 0.8314, compared with 0.2780 for the baseline. These results provide directional evidence that combining multiple historical signals can produce a more useful prioritization ranking than the simple baseline, while the output remains decision-support evidence rather than a guarantee of future search performance.

1. Introduction / Problem Statement

Content teams may have many webpages that could potentially benefit from investigation or improvement. Reviewing every page manually is expensive, so a prioritization mechanism can help identify which pages should be examined first.

This project focuses on the lane of search discoverability and content improvement. The decision supported by the analysis is: which webpages should be prioritized for content investigation?

The ML task is formulated as a classification problem. Historical page-level search-performance signals are used to estimate whether a webpage is likely to exhibit the defined declining-performance outcome.

Core-first principle: The model is used to support an existing content-investigation workflow. It does not replace human review or claim to determine why a page performs poorly.

2. Data

Data source

The analysis uses the FlyRank internship warehouse release accessed through the provided data environment.

Unit of analysis

The analysis unit is one content item for one client, represented by the combination of:

  • Client identifier
  • Content identifier

Time windows

Window Purpose
February 2026 Historical feature window
March 2026 Outcome / label window

The feature window precedes the label window. This separation helps prevent future information from entering the feature set.

Feature selection

The model uses historical search-performance signals including:

  • Search impressions
  • Search clicks
  • Click-through rate (CTR)
  • Average search position
  • Number of days with available search data

Data exclusions

Pages without sufficient historical search activity were excluded from the modeling universe using minimum impression and click thresholds. This was intended to reduce extremely sparse observations and create a more meaningful comparison population.

The final analysis frame contained 29,353 content observations after requiring measurable outcome-window data.

3. Methodology

Target / proxy

The target is a binary outcome representing whether a content item experienced the defined search-performance outcome during the March 2026 label window.

The target is treated as a proxy for identifying pages that may deserve further investigation. It should not be interpreted as a direct measurement of content quality.

Baseline

Week 4 established a transparent baseline ranking rule using two signals: CTR gap and search-impression volume.

The baseline combines:

  • 60% CTR-gap score
  • 40% volume score

The baseline was intentionally simple and interpretable so that the ML model could be compared against a clear non-ML alternative.

Machine-learning model

A decision-tree classifier was used as the initial ML model. The model was trained using the historical feature window and evaluated on a held-out test split.

Validation design

The data was divided into training and test sets using a stratified split. The same held-out test set was used for comparing the ML model and the Week 4 baseline.

Evaluation metric

ROC-AUC was used to measure ranking discrimination. Because the intended use case is prioritization, the analysis also considers top-ranked recommendations rather than relying only on a fixed classification threshold.

Leakage check

A deliberate leakage experiment was performed during the data-contract stage by introducing a future label-window variable into the feature set. The resulting near-perfect performance demonstrated why future outcome variables must not be included in the honest feature set.

The final model excludes future March outcome variables from its predictive features.

Interpretation

The ML model produced substantially stronger ranking discrimination than the Week 4 baseline in this evaluation. The difference suggests that combining multiple historical signals through a learned model can be more effective for prioritization than the transparent baseline rule.

However, this result should be interpreted within the evaluation setup. A higher ROC-AUC demonstrates better discrimination on this test split; it does not prove future production performance or guarantee improved search outcomes.

5. Limitations

This analysis provides directional, decision-support evidence based on observed historical search-performance patterns.

The model predicts the defined outcome using historical page-level signals, but the results do not establish that any specific content characteristic causes search-performance changes.

The model cannot predict Google's ranking decisions, guarantee future search performance, or guarantee that refreshing a page will increase clicks or rankings.

The baseline and model are evaluated on the same held-out test split, but the observed performance should not be interpreted as proof of production performance on future unseen data.

The ranked recommendations should therefore be treated as a prioritization queue for content investigation and improvement, rather than as guaranteed actions or outcomes.

Public-facing analysis must also avoid client names, domains, private queries, credentials, raw private exports, and claims about Google's ranking algorithm.

6. Ranked Recommendations

The model output is intended to create a ranked prioritization queue for content investigation.

Recommended action playbook

  1. Review the highest-ranked pages first.
  2. Inspect search visibility and engagement signals for the selected page.
  3. Investigate whether an identifiable content or search-discoverability opportunity exists.
  4. Prioritize pages where a content improvement is feasible and supported by evidence.
  5. Re-measure performance after changes where appropriate.
Important: A high model score indicates prioritization value. It does not guarantee that a content refresh will improve rankings, clicks, or other search outcomes.
